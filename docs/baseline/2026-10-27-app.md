# Baseline — the desktop app and the sensei MCP tools, 2026-10-27

The starting point the user asked for (2026-10-27): every screen of the app, every clickable element on it, its console,
and — on the user's correction that a call which does not fail is not yet a right answer — every sensei MCP tool run and
its answer checked against what is true. The core targets are diagrams, instruments, libraries, metrics and the dōjō sync.

How it is produced, so it can be produced again:

- **Screens.** `bun run test:inspect -- baseline-crawl` (app/e2e/tests-inspect/baseline-crawl-inspect.spec.ts) visits
  every route under `src/routes` against the real daemon, records what renders, the console, and every clickable element
  it clicked. Nothing that changes data is clicked. `CRAWL_ONLY=/a,/b` re-crawls routes. The report is
  `scripts/baseline-report.py /tmp/sensei-baseline.jsonl`.
- **Tools.** `bun run test:inspect -- tool-calls` runs each sensei tool through the Playground, in the sensei workspace,
  and holds the answer to one worked out without the tool (app/e2e/tests-inspect/tool-oracles.ts): the source (ripgrep),
  git, the installed packages, or the database. Every tool the server lists is accounted for.

## On every screen

The dōjō sync has failed every minute since at least 2026-10-22: "all 2 personas failed: … stored session unreadable:
keychain access needs approval". Each daemon reinstall changes its code signature, and macOS revokes the Keychain
approval (#282). This is why the production dōjō shows no workspaces: workspaces there are filed by the sync. It clears
once Keychain access is approved ("Always Allow" in Identities); #282 (Developer ID signing) ends it for good.
